1. What is Haze Seas?

Haze Seas is a Roblox adventure / combat RPG from [HS] Haze Studios. It is a One Piece–inspired open-sea experience: islands, fruits (devil fruit powers), swords, races, fighting styles, bosses, sea events, ships, fishing, and long-term mastery grind.

Platform Roblox

Players progress through seas, unlock abilities, collect tradeable items, and compete or cooperate around events (storms, superbosses, merchant spawns, and more). Community trading is a big part of the culture—so people need a trustworthy place to look up values, drop routes, and systems.

2. What is Haze Atlas?

Haze Atlas is a fan-made companion website for Haze Seas. It is not an official Roblox product and is not affiliated with Haze Studios.

It packages game knowledge into one fast UI:

  • Value list — fruits, swords, accessories, gamepasses, perm fruits
  • Trade tools — calculator, compare, trade ideas, local history
  • Official guides — codes, bosses, races, styles, seas, systems
  • Power gallery — official moveset videos (lazy-loaded)
  • Progression tools — mastery XP planner, builds, collection (local)
  • Release tracking — released / unreleased status with confirmed overrides

Think of Atlas as a chart room next to the game: values from the community market list, gameplay facts from official Trello, stored as static files so the site is fast and hostable on GitHub Pages.

3. How the website works

Haze Atlas is a static web app. There is no login server and no live database behind the public site. The browser loads HTML/CSS/JS plus JSON “snapshots” that were prepared ahead of time.

Key files

index.html App shell (sidebar, top bar, dialogs) UI structure
data.json Item values, demand, rarity, PvP/PvE notes Value list & trade math

Runtime layers (JS)

2

3
enhancements.js Companion features: power gallery, builds, collection, release tracker, trade pro.
4
redesign.js + CSS Visual shell: polished sidebar, top bar, dashboard presentation.

How data gets into the repo (offline sync)

Maintainers run Python tools under tools/ to rebuild snapshots from the live sources, then commit/deploy the updated JSON and media:

  • sync_value_sources.py → trade values into data.json
  • sync_trello_content.py → encyclopedia into content.json
  • sync_trello_details.py → per-item Trello details / images
  • download_power_media.py → official power videos
  • thumbnail / poster generators for web-friendly art

There is also an optional Firebase checker under functions/ that compares the published Atlas snapshots against Trello and the sheet for drift.

4. How refresh works

The top-bar refresh control is easy to misunderstand. Here is the precise behavior:

Refresh does not scrape Trello or Google Sheets live in the browser. A GitHub Actions workflow (sync-data.yml) pulls sources every ~2 hours, commits updated JSON to the repo, Pages deploys it, and Refresh re-fetches those files with a cache-busting query string.

A
GitHub Actions produces snapshots Workflow runs sync_value_sources.py --write, Trello content/details syncs, writes sync-meta.json, and commits when anything changed.
B
What the button does Calls window.haze.refresh() → cache-busted fetch of data.json, content.json, trello-details.json, and mastery. Values/guides in memory are replaced; the status chip updates.
C
Auto refresh while the tab stays open About every 2 hours, the app reloads the same way so a long-open tab can pick up a newly deployed Actions snapshot.
D
Local “changelog” of values When a reloaded snapshot differs from the previous one this browser saw, Atlas records those diffs in localStorage (recent changes drawer). That history is per-device, not a global market feed.

Status chip (“2h ago”)

The quiet status text in the top bar is a relative timestamp for when this browser last successfully checked / loaded the bundled snapshot—not a live ping of Roblox servers.

Browser refresh Reloads deployed JSON
Maintainer sync Updates the snapshot
Roblox game API Not connected

5. Sources & trust rules

Atlas deliberately separates market estimates from official gameplay facts. Conflict policy lives in source-policy.json.

Source Role Authority
Official Haze Seas Trello
trello.com/b/nn8bpTB0… 		Gameplay records, obtainment, bosses, codes, systems, official media Authoritative for game facts
Published value spreadsheet
Google Sheet (public) 		Trade values, demand, rarity, PvP/PvE notes used in data.json Primary for values
Vaulted Values X
haze-seas.vaultedvaluesx.com 		Secondary market cross-check / reference Secondary only — does not override the sheet
Mastery XP table
Bundled as mastery-xp.json 		Exact UI XP rows 0–500; estimates aligned to official mastery ratios Progression calculator input
Release overrides
In app-config.json 		Owner-confirmed release status when Trello naming is ambiguous Manual verified overrides

Conflict policy (short version)

  • If two value sources disagree → keep the Google Sheet value in Atlas.
  • Vaulted Values X may be used as a cross-check, never as the replacement.
  • If gameplay text disagrees with community rumor → trust official Trello.

Community value list caveat

Spreadsheet values are estimates based on community trading activity. They are not official Roblox prices and not a guarantee of any deal. Demand moves; always use judgment in-game.

6. What stays on your device

Atlas stores personal state in the browser’s localStorage only. Clearing site data or using another browser/device starts fresh.

  • Favorites
  • Collection marks (owned / wanted / trade)
  • Saved builds and saved trade offers
  • Trade history / recent offers
  • Theme & density settings
  • Local value-change changelog snapshots
  • Nav open/closed preferences

None of that is uploaded to a Haze Atlas server—because the public site is static files.
